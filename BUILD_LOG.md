# BUILD_LOG

## Plan

### What we are building
A front-end-only, clickable prototype of Rizzfitt Organizer OS in the dark "Night Court" style. A new organizer signs in with a mobile OTP, answers a 7-step guided setup that branches by sport and event type, watches their event app assemble in 3D, and lands in a lifecycle-organized workspace (Before, During, After) that only shows the modules their answers switched on. The same mock store (Zustand, persisted to localStorage, synced across tabs) drives every other surface: the player microsite, a phone umpire scoring pad, broadcast-style court TV screens and the Rizzfitt HQ console with approvals, take-over and the "What's new" scope page. Everything is invented data, simulated async, and procedural 3D with fallbacks.

### Contradictions or gaps found, and decisions
1. **Routes for microsite:** `docs/04` and the README say public pages live at `rizzfitt.com/e/[slug]`, while the prototype routes use `/p/:slug` (because `/e/:eventId` is the workspace). Decision: route stays `/p/:slug`; the displayed public address everywhere reads `rizzfitt.com/e/[slug]`.
2. **Match count "about 190":** the exact number depends on the format algorithm. Decision: matches are generated by the real draw and bracket algorithms; the status strip computes "X of Y matches done" from data. It lands near 190.
3. **Event moments:** only the hero event needs Before launch / Registrations open / Draw day / Match day / Finished. Decision: each moment regenerates the hero event deterministically from the seed with stage parameters.
4. **Logo and Gilroy:** `assets/` has no brand or font files. Decision: text wordmark with an orange rounded-square mark, Outfit font, and a dev-only warning in the Prototype switcher.
5. **3D spot icons:** downloading Fluent Emoji / 3dicons at build time adds a third-party fetch step. Decision: spot icons are rendered as Lucide glyphs on glowing 3D-looking orbs (allowed fallback in `design/08` step 3). Logged as a deviation.
6. **QR codes:** needed in share sheet, umpire links, tickets and TV. Decision: add `qrcode.react` (tiny, no network) since faking a QR would be misleading.
7. **Tailwind version:** v4 with `@theme` mapped to the CSS custom properties in `tokens.css` (the tokens remain the single source).
8. **Rahul's new event:** demo Act 2 uses 6 courts and different categories than the hero event; the SW-09 checklist copy uses the draft's own name and counts.

## Decisions
(see the plan above, plus:)
- **Entries** = registrations that are paid or pending. Waitlist, refunded and withdrawn are not entries. One selector (`src/store/selectors.ts`) feeds every screen.
- **Check-in is per player across the event** (a player in two categories checks in once), so check-in counts are "players", matching "128 of 152 checked in" copy.
- **Match total** comes out at 213 (docs say "about 190") because the real algorithms create the full group stages; the status strip computes it.
- **Demo clock**: data carries a fixed `now` per moment (match day = 18 Oct 2026, 4:20 pm IST). New actions nudge it forward 30 s so timelines read in order.
- **Fees**: one total per payment computed at a demo 3% for online payments so Money reconciles; rates show only as `[PLATFORM FEE]` placeholders and only in HQ.
- **immer** added (zustand's immer-style updates via `produce`) to keep store actions readable. Small, no network.
- **GPU tier**: drei `useDetectGPU` downloads benchmark data at runtime, so `useQuality` uses a local heuristic (renderer string, cores, memory, mobile UA).
- **3D text** (podium numbers, module labels) uses canvas textures, because drei `Text` fetches a font from a CDN by default.
- **Playwright** for screenshots: the Claude browser pane refused localhost, so `scripts/shot.mjs` drives headless Chromium (software GL, so FPS in screenshots is not representative).

- **Ranges use hyphens** ("9-6", "7 to 29 Nov"): the brand guide uses en dashes, but CLAUDE.md bans them in UI copy. Confirmed by the product owner: CLAUDE.md wins.

## Deviations
- Icon wells follow the brand guidelines (a #2B2B2B circle with an orange Lucide icon) instead of the 3D orbs in design/08. The brand guide wins on visual rules.
- The brand rule "nothing loops except the LIVE dot" is followed everywhere except the landing hero court and the Court TV display, which CLAUDE.md asks to keep as 3D moments. Both still pause off screen and stop under reduced motion.
- The demo script's trophy reaches 100% because SW-08 counts as reviewing the page and Rahul invites one umpire and adds one sponsor during setup (the e2e test does this).
- Court map score bugs are slim labels over the tiles; full scores are in the courts list beside the map so labels never overlap.
- Cricket and football scoring are point counters, not ball-by-ball.

## Brand pass (rizzfitt-brand-guidelines.html)

- **Logo:** the official athlete mark and wordmark from the guidelines are in `public/brand/` (orange and white on dark, orange and ink on light, mark only) and in `src/lib/logoPaths.ts`. The favicon is the white mark on an orange tile. Lockups never render below 120 px wide; the mark never renders below 20 px.
- **Tokens:** `src/theme/tokens.css` now uses the brand values: ground #0A0A0A, surfaces #141414, #1A1A1A and #1E1E1E, controls #2B2B2B, divider #333, hairline at 7% white, text #FFF/#AAA/#888 (#555 only for disabled). Orange #F36B1C is the one action colour (pressed #E45112). Red is only for LIVE, errors and destructive actions. Warnings use Orange 300. Deep Blue is only for HQ. Avatar hues are only for category dots, team crests and avatars.
- **Type:** Inter for UI on the brand scale (display 30/36/800, title 20/28/700, headline 16/24/600, body 14/20, callout 13/18, caption 12/16, label 11/700 caps). Urbanist (Gilroy fallback) is only for marketing display type. Score numbers scale from 36 px down to 22 px on phones so money never overflows.
- **Components:** buttons (52 px primary with glow, pill secondary, 30 px small outline), 52 px inputs with an orange focus ring, 16 px cards, pill chips, 6 px tags, outlined LIVE badge with a 1.4 s dot, an orange segmented control, step dots with a 28 px active bar, 24 px sheets on a 65% scrim, and 64 px table rows.
- **Event colour removed:** the brand allows one action colour, so organizers now pick a page ground (Court Black or Charcoal) instead of an accent colour. Every event uses Rizz Orange.
- **Motion:** 150/250 ms. Card tilt, floating icons, the trophy sway, the paddle bounce loop and TV marquee are gone.
- **Voice:** "Customer" became "Paid by" and "Users and roles" became "HQ team and roles".

### (i) help everywhere
- `src/lib/help.ts` holds one plain-words explanation per visible label (about 200 entries). `Q`, every field, toggle, checkbox, card header and page header looks its label up and shows a 14 px (i) when an entry exists. Obvious fields (first name, email) have none on purpose so the UI stays quiet.
- The (i) opens on hover or focus and stays open on tap. It is announced as "More info" with the help text as its description, so it never clashes with the field's own label.
